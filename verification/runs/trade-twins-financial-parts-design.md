# D046 financial worker: original paired work units

This is the next implementation design, not an implemented or accepted workflow. It extends [the durable-worker design](trade-twins-durable-worker-design.md), the source/matching/financial contracts and the original83 requirements,422 mandatory cases and120 baseline combinations. Source: [AI Pathways / Brendan](https://www.youtube.com/watch?v=z97PnFIPoFg). Private host-engine parity remains unverified.

## Existing foundation

`data/dev026/next-src` contains the causal features, exact amounts and grading, original saved-source reader, independent one-trade financial kernel, original atomic reservation,20001 prespecified preparation/financial occurrences and the owned preparation helper. The helper is not yet dispatched by the product worker. No trade-twin API or UI is exposed. The live app remains0.25.

Preparation seals the complete outcome-blind plan atomically with its original trial checkpoint. Resume independently rebuilds the plan against current verified inputs and compares the original bytes/computation/events; a missing/corrupt seal is not permission to replace a committed preparation. Uncommitted attempt files remain separate. Full source authority is checked before preparation and again before sealing. These components do not complete or grade a financial comparison.

## Declare work units before profit

Derive a deterministic part partition from the already frozen source trade count, never from outcomes or observed runtime. Bound ordinary parts by both set count and member work; an initial design target is at most100 sets and1000 source-trade assignments per part. A single large original cohort must still remain whole, even when it exceeds that member target. The final supported envelope and measured limits must be explicit. Both policies use the same ordinal draw in each part. Freeze the partition before candidate P&L.

Preserve all10000 set occurrences for each policy, including duplicate draws and failed members. A set with any failed member is explicitly failed; it cannot receive a favorable partial total. Expected inability to fill or maintain a short stays in the financial record. A system/data/arithmetic error preserves the failed computation attempt and any orphaned artifacts and stops publication; it does not redraw or drop the member. Complete set totals use canonical Decimal amounts and `exact_total`, never float aggregation. The strict499/500 threshold, ties and conditional exact interval remain unchanged.

## Original parts and reusable books

One original part contains its ordinal range, paired set records, draw hashes, complete source membership and references to every member book. It also carries books first computed in that part. A book key binds parent authority, sealed matching plan, the complete selected match, policy, original rule/cost/account/quantity, source data/actions/news/borrow and clock identities. Assignment or eligibility must never depend on a cached profit.

A derived book index points to an original committed part, original book offset/key and canonical book hash. Before reuse, verify the exact original part bytes and commit event, locate the bound book, and compare its full input descriptor and canonical financial hash. A locally consistent/rehashed index cannot replace original authority. Verify per-part index counts and bindings against original parts so deleting a cached entry cannot silently turn a committed book into a new computation. Explicit index repair may rebuild metadata from original evidence without executing finance. Do not adopt an orphan part/book as committed evidence.

Bound decoded-part and in-memory book caching explicitly. Every set occurrence remains distinct even when books are reused. Cached arithmetic is not another independent strategy or independent market observation. Statistical strategy counts must keep the trade-twin roles separate from the original strategy selection count.

## Ownership and atomic publication

Start the prespecified set trials in a bounded owned transaction before their numerical work. Keep an actual attempt for each occurrence and preserve previous attempts after cancellation or worker death. Prepare unique attempt files without overwriting an earlier attempt or committed part. Compute against immutable verified input observations, checking cancellation between members and at bounded inner steps.

Check complete original source authority before each work unit and again after its new/reused financial work. Then, under the owning transaction, recheck parent/trial/input/protected-scope and source-byte bindings, fence stale workers and cancellation, and atomically checkpoint every occurrence with the original part commit event and book-index additions. Nothing from a part whose closing authority fails may become reusable or enter grading. An earlier computed/orphaned attempt remains evidence of attempted work, not a successful set.

Factor transaction-aware journal helpers rather than opening nested write transactions. The original reservation already exposed and corrected that lock failure. Use bounded indexed event/part lookups, not repeated scans of all job payloads. Original trial/attempt/start/checkpoint evidence must agree with committed parts on reopening. Actual interpreter-death tests are required at each file/computation/checkpoint/index/publication boundary; injected exceptions alone do not certify process-death recovery.

An ineligible whole cohort publishes a reason with zero executed financial sets. Its ungenerated occurrences need explicit original ineligibility provenance; do not fabricate completed numerical trials. A qualifying financial result requires all original10000 ordinals, full membership and valid original parts for each policy. Reopen/audit saved artifacts before final grading and publication.

## Product and verification

Publish compact original summaries and a committed part-manifest binding, with seek pages for sets and member books. Status/poll/control reads must not decode all financial parts. Large full-cohort member lists require bounded pages. JSON/CSV/offline exports stream saved originals and retain raw exact amounts, complete failures, assumptions and both interpretations. Displayed source assumptions belong to the saved result, not the current form.

Connect the request model, original-parent API, worker dispatch, progress/cancel/resume, history/reopen and interface only after the durable path exists. Older reports remain readable and explain when a new explicitly identified account under the current engine is required. Reopen/rerun must never expose consumed final-test dates. No caller override of count, seed, cost, policy or original quantity is accepted.

Verify original linkage races, every authority/index/part/book/sidecar/trial tamper boundary, exact-money/tie/499/500 cases, both policy orders with shared draws, all failures and losing books, stale workers, actual death/recovery, pages, exports and UI response ownership. Execute actual10000-set completed-worker workloads with losses, actions, borrowing/recalls and larger cohorts. Independently audit complete financial books and all retained set/draw lineages; measure wall time, RSS, disk and control/page bounds. The earlier flat one-trade prototype remains separate evidence. Finish unchanged numerical gates, current regression, owned idle integration and live-store preservation before proceeding to the remaining research funnel and final plan-wide acceptance.
